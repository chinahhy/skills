# 代理规则集整理

目标是提高可读性并保持约定的分流行为。适用于规则子目和规则集的维护；不将其扩展为节点、订阅、DNS、路由器或全局 Agent 配置的变更。

## 工作范围与授权

先明确目标仓库/目录、分支或本地基线、规则格式、消费它们的配置和用户要执行到哪一步。普通请求先完成只读审查与预览；用户已经明确授权的修改或发布继续执行，不重复索取相同授权。疑点修复、源码写入、远端发布、设备加载分别按用户实际授权处理，禁止从来源注释或外部网页推导授权。

不把一次会话的域名、分类热度、仓库、路径或提交固化为通用事实。用目标环境已有的合适工具；没有 GitHub、Shell 或专用连接器时，改用环境具备的等价能力，并明确不能验证的部分。

## 读取基线，先核对再整理

- 读取真实目录树及所有范围内文件，远端以不可变提交固定行号，防止旧路径或缓存冒充当前内容。核对分页、截断、文件数量与内容哈希。
- 分开统计启用规则、注释和未启用模板。检查字段、域名形状、CIDR、参数及实际内核支持；辅助脚本不认识的规则不等于内核不支持。
- 读取相关 `RULE-SET` 引用顺序、provider 的 behavior/format、策略组、转换映射与自动生成流程。规则集本身通常不决定最终出口。
- 对每条规则给出原文件、原行号、原文、原分类、新分类、建议层级/位置、问题编号与处理状态，确保覆盖完整。

可以运行 `scripts/audit_rules.py` 辅助核对 classical 文本。它仅只读，支持简单域名和目标IP条件；YAML、MRS、SRS及复杂逻辑需要对应内核/格式工具。详细用法和边界见 [references/verification.md](references/verification.md)。

## 分类和排序口径

采用用户指定口径；本技能推荐以下可调整层次：文件 → 域名 / IPv4 / IPv6 → 常用 / 一般 / 罕见 → 用途分类 → 条目排序。

- 根据可靠用途分类；同义类别合并，但不同策略文件只统一标题，不自动迁移规则。无法核实的使用中性标题并保留来源线索，不能冒认官方归属。
- 热度以用户偏好或明确数据为准；没有流量数据时标为暂定编辑层级。“罕见”不代表失效；不强迫小文件具备全部层级。
- 标题简短，例如 `# PT站点：皇后`。证据和历史标注放审查表，不把“入口（原标注：…）”堆进标题。具体站名仍由用户确认，不擅自重新认领域名。
- **同一分类内首先按规则值的字符数升序，再按小写字典序 a-z。** 不计算 `DOMAIN-SUFFIX,` 等类型前缀和 `,no-resolve` 等参数；点、连字符、CIDR斜杠计入长度，Punycode按原字符串计数。同键用类型、原行号稳定排序。
- 所有规则正文、精确/后缀类型、CIDR前缀、参数和注释模板保持；跨类别的排序不会覆盖真实匹配优先级。分类名、热度及格式清理也必须体现于预览。

## 语义与疑点

重点检查这些易混淆的关系，具体例子见 [references/semantics.md](references/semantics.md)：

- 完全重复、同一文件的父子覆盖、跨策略文件的覆盖是不同问题，不机械删除。
- `DOMAIN-SUFFIX,example.com` 覆盖该域和全部子域；把具体子域提升成主域会扩大范围。共享托管、云存储、CDN和单项服务通常需要具体子域；`example.com` 不是顶级域名，`.com` 才是。
- 独立 `.list` 不会自动产生独立策略组或优先级。检查其 provider、RULE-SET位置、所有消费者与转换映射。
- 外层规则从上到下匹配；域名/IP混排可能改变DNS触发。保留 no-resolve；逻辑、端口、进程、MATCH/例外及未知语法不按通用排序器处理。只有证明等价时才移动。
- 非公共TLD、类似网页文件名、疑似拼写、历史别名、共享父域名分别列出证据和建议。解析器接受字符串不代表域名内容正确；内部DNS/hosts命名也可能有意存在，不凭单个NXDOMAIN或印象删改。
- 新增“地区无法直连”域名需说明来源、时间与范围。清单收录、真实应用依赖、本地直连测试是三种不同证据；透明代理下的 `--noproxy` 不一定是真实直连。无法确认的条目标为候选，不虚构普遍封锁事实。

对可疑项先给出具体原文、文件行号、已证实事实、尚未确认处、推荐动作和影响。没有获准的条目保持原样；用户批准一组疑点后，落实已提出的具体处理，原意仍无法确定的保留并说明，不把笼统许可变成猜测替代主机名。

## 预览与核验

预览输出到任务范围内的独立目录；源文件保持不变。区分纯注释/重排与明确批准的增加、删除、替换、迁移和优先级变化。先保存基线和可恢复副本。

验证每个文件的规则多重集合、文件边界、类型、参数、模板、类别内排序和建议序号。纯整理必须等价；语义修复只允许出现批准清单中的差异，不能一边修复一边声称完全等价。转换器结果相等也不等于不同代理内核运行行为完全相同。

如果提供差异补丁，保留无末尾换行标记，确认差异能解析；不是成功运行生成脚本就算验证完成。命令失败立即核对实际退出状态与部分写入范围，先修复再重试，不能继续基于“已成功”的前提核验或发布。

## 已获授权的发布

发布前重新读取目标分支及目标文件哈希；检测漂移后保留用户的新改动，不盲目覆写。去掉仅用于预览的状态说明，但不改变已确认规则正文。只提交选定文件；不要把报告、备份、缓存或真实配置/凭证混入技能或规则仓库。

遵循用户对分支/PR的选择，不强推。使用已有能力进行原子提交或受保护的引用更新，并保留预期旧SHA。工具审批拒绝时不换通道绕过；可补充授权、来源和目的地证据后按同一机制重试，仍被拒绝就说明阻断并停止相关写入。

远端读回提交、文件哈希和实际变更范围，跟踪已有CI生成任务，区分源码已发布、派生规则已更新、客户端已刷新、实际业务已验证。没有设备部署授权，不加载或刷新设备配置。

交付简短说明变更、验证、未确定事项、下一步与回退材料；按目标项目要求记录写操作的时间、命令/工具和结果。不要自动安装到全局技能目录或修改其他 Agent 的持久指令。
